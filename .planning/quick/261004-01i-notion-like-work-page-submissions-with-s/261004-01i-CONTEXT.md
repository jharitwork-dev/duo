# Quick Task 261004-01i: Notion-like work page submissions - Context

**Gathered:** 2026-10-04
**Status:** Ready for planning. 261003-wuo and 261004-02p are merged, applied and deployed (main ≥ 0f578d7).

<domain>
## Task Boundary

The user (Thai): "ตอนส่งงานอยากให้ส่งเป็น text เฉย ๆ ได้คล้ายการทำ page ใน notion อยากให้นักเรียนทำ to-do list ย่อยได้
แล้วติ๊กได้ เขียนข้อความได้ กด add file ได้ ซึ่งทุกงานไม่จำเป็นต้องแนบไฟล์ ให้ครูกำหนดตอนส่งงาน"

Replace the file-only submit flow with a **work page** per to-do:
- **Rich text body** (Notion-like): headings, paragraphs, bullet lists, bold/italic, links.
- **Sub to-do checklist** the student creates inside the page; items are tickable (checked state saved).
- **Files** attached to the page (R2 presigned upload, reusing `createSubmissionUploadUrl` / `presignPut`).
- **Autosave** (debounced ~800ms, plus on blur and before submit) with a "บันทึกแล้ว · 13:59" indicator. Clicking **"ส่งงาน"**
  snapshots the page into a submission (status `pending`) for the teacher. While a submission is `pending` or `approved`
  the page is read-only, showing "ส่งแล้ว รอตรวจ" or "ผ่านแล้ว". After `rejected` (ต้องแก้ไข) the page becomes editable again
  and the student resubmits; submission history keeps every round (ครั้งที่ n).
- **Group to-dos: ONE shared page per group.** Any member can edit or submit. Not realtime: last write wins per save,
  plus a light "มีการแก้ไขจาก <name> เมื่อ …" notice when the server version is newer than the client's base (simple
  `updatedAt` check on save; on conflict, reload the server version and keep the user's unsaved text in a recoverable
  draft box). Individual to-dos: one page per student.
- **Teacher sets the file requirement per to-do** with `todos.file_requirement` enum `('none','optional','required')`,
  default `'optional'`:
  - `none`: the page has no file section.
  - `optional`: files may be added.
  - `required`: "ส่งงาน" is disabled until at least 1 file is attached, with hint "งานนี้ต้องแนบไฟล์อย่างน้อย 1 ไฟล์".
  Set in the teacher to-do create/edit form (and in the multi-group assign dialog from 261003-wuo), shown on the student
  page as a small badge. Templates may carry `fileRequirement` per to-do (optional field, default optional).

### Data model (additive only — the DB is shared with the LIVE site)
- `work_pages`: `id, todo_id FK cascade, group_id FK (nullable), user_id (nullable), content jsonb not null default '{}',
  updated_at, updated_by`, plus a unique index ensuring one page per (todo, group) for group to-dos and per (todo, user)
  for individual to-dos (two partial unique indexes).
- `work_page_files`: `id, work_page_id FK cascade, file_name, file_key, content_type, file_size, uploaded_by, created_at`.
- `todos.file_requirement` (enum, default 'optional').
- `submissions.content` jsonb nullable = the snapshot of the page at submit time. Files are snapshotted by copying
  `work_page_files` rows into `submission_files` (same R2 keys; never delete R2 objects still referenced by any submission).
- Provide a migration script in the same style as 261003-wuo (`--dry-run` / `--apply`, transaction, idempotent).
  The executor may only run `--dry-run`.

### Editor
Use **Tiptap** (already chosen in `.planning/research/STACK.md`): `@tiptap/react`, `@tiptap/pm`, `@tiptap/starter-kit`,
`@tiptap/extension-task-list`, `@tiptap/extension-task-item`, `@tiptap/extension-link`, `@tiptap/extension-placeholder`.
Use the current major that supports React 19, and check its docs/types in node_modules after install. Store the editor
JSON in `content`. Render read-only snapshots (student history, teacher view) with the same extensions in non-editable
mode. Add a slash-command-free Notion feel: a placeholder "พิมพ์รายละเอียดงาน หรือกด [ ] เพื่อสร้าง to-do", markdown input
rules (`- `, `[] `, `# `), and a small toolbar (H, B, I, bullet list, to-do list, link) that sticks at the top on mobile.
Show a checklist progress chip "to-do 3/5" computed from taskItem nodes.

### UI (Cocoon CI; no Figma for this — Claude designs)
- Student to-do page (`/todo/[id]`, student branch): title + phase subtitle + status pill + teacher's detail card
  (รายละเอียดงาน / สิ่งที่ต้องส่ง from 260928-jkg). Then the **work page card** (white, radius 16, editor inside, autosave
  indicator, checklist chip), then the **files section** (per file_requirement, reusing the existing upload rows and dropzone
  styling), then the sticky bottom bar on mobile / right-aligned on desktop with "ส่งงาน" (orange; for resubmit after
  rejected, yellow "ส่งอีกครั้ง", as in design/mac home-8). Keep the existing confirm dialog, adapted to the summary
  "ข้อความ · to-do 3/5 · 2 ไฟล์". Submission history + reviewer comment card stay.
- Mobile: the editor is full-width inside the card; the toolbar scrolls horizontally; tap targets are ≥ 40px.
- Teacher views of a group's to-do (and later the Phase 4 review screen) render the latest submission snapshot read-only,
  plus the live page read-only with a "ฉบับล่าสุด (ยังไม่ส่ง)" label.
- Node status on the home path is unchanged: none → pending → rejected/approved, driven by submissions. Optional: show
  "กำลังทำ" (in progress) when a page has content but no submission. Claude's discretion; reuse the blue-soft pill if added.

### Also in scope (security, found by 261004-02p verifier)
`getAttachmentDownloadUrl` (src/server/actions/todo.ts) has no classroom-membership check: any signed-in user with an attachment id can get a
download URL. Gate it: classroom editors of the to-do's classroom, or students in the to-do's group. Apply the same rule to every new
work-page file URL action.

### Current conventions to follow (from 261004-02p)
- Server actions return `ActionResult` (`src/lib/action-result.ts`) with Thai error messages for expected failures; auth failures throw.
- Teacher mutations authorize via `assertClassroomEditor` / `assertTodoEditor` in `src/server/phase-helpers.ts`; the static test
  `authz-coverage.test.ts` must cover any new action files.
- Destructive UI uses `src/components/cocoon/confirm-dialog.tsx`; R2 cleanup via `src/lib/r2-cleanup.ts` (best-effort, after commit).
- Schema changes ONLY via a reviewed script in `src/db/migrations/` (`--dry-run` / `--apply`); never drizzle-kit push.

Out of scope: realtime collaborative editing, comments on pages, Phase 4 review actions, notifications, LINE.

<specifics>
## Specific Ideas
- R2 is not configured yet (keys pending from the user). File features must fail gracefully with "ยังไม่ได้ตั้งค่าที่เก็บไฟล์"
  instead of crashing, and text/checklist submission must work without R2.
- Sanitize nothing on the server beyond validating the JSON shape with zod (Tiptap JSON, size cap ~200 KB). Render only through
  Tiptap (no dangerouslySetInnerHTML).
- Access rules: a student can read/write only their group's page (group mode) or their own page (individual mode); teachers of
  the classroom can read; writes are blocked while the latest submission is pending/approved.
- Unit-test the pure helpers: checklist progress from JSON, submit eligibility (file_requirement × file count × status), and
  page ownership key (group vs user).
</specifics>
