# Quick Task 261004-01i: Notion-like work page submissions Summary

Each to-do now has a Tiptap v3 work page (rich text plus a tickable checklist plus optional files). It autosaves with conflict detection and is snapshotted into a pending submission on "ส่งงาน". Group to-dos share one page per group; individual to-dos get one page per student. Teachers choose none / optional / required files per to-do. Attachment and file download URLs are now restricted to classroom editors and students in the to-do's group.

## Installed Tiptap (verified from node_modules)

All `@tiptap/*` resolve to **3.31.4** (one version). APIs checked in the installed d.ts / source before use:
- `useEditor(options & { immediatelyRender: false }) → Editor | null`, `shouldRerenderOnTransaction`, `useEditorState({ editor, selector })`, `EditorContent`.
- StarterKit v3 bundles Link, Underline, ListKeymap, TrailingNode, Dropcursor and Gapcursor. It is configured with `link: false, codeBlock: false`, and Link is registered once from `@tiptap/extension-link`, so there are no duplicate extension names.
- `@tiptap/extension-task-list` / `-task-item` re-export `TaskList` / `TaskItem` from `@tiptap/extension-list`; `@tiptap/extension-placeholder` re-exports `Placeholder` from `@tiptap/extensions`.
- The TaskItem input rule `/^\s*(\[([( |x])?\])\s$/` already accepts `[] `, `[ ] ` and `[x] `, so no custom rule was needed.
- `setContent(content, { emitUpdate })`: v3 takes an options object (default `emitUpdate: true`). The code passes `false` explicitly.
- `useEditor` with `deps = []` re-applies changed options on every render but keeps `editable` as it is. For that reason the extensions are memoised once, and `editable` changes go through `editor.setEditable` in an effect.
- The schema-sync test runs `getSchema(workPageExtensions())` under vitest's node environment without problems. No fallback was needed.

## Deviations from Plan

### Auto-fixed / adjusted

1. **[Rule 3 - Blocking] Local node_modules in the worktree.** The worktree had no node_modules, so Node would have fallen through to main's. Ran `npm ci` locally, then `npm install @tiptap/...`. Main's node_modules was not touched. `.env.local` was copied from main; it is git-ignored and was never committed.
2. **[Rule 1 - Bug] Mobile submit bar placement.** A `fixed inset-x-0 bottom-0` bar would sit under the app's own fixed `BottomTabBar` (z-40, bottom-0). The bar is instead `sticky` just above the tab bar (`bottom: calc(68px + safe-area)`, `md:bottom-[100px]`) and static/right-aligned at lg. No extra page padding is needed.
3. **[Rule 2] `formatBangkokTime` added to src/lib/format.ts.** The "บันทึกแล้ว · HH:mm" and conflict times are fixed to Asia/Bangkok so SSR and client output match (same approach as formatSubmissionDate).
4. **[Rule 2] Extra file `src/components/todo/file-requirement-select.tsx`.** One shared Select for the assign dialog and the edit form. The edit form labels it "ไฟล์แนบตอนส่งงาน" because that form already has a teacher-attachment "ไฟล์แนบ" section.
5. **`isSaveConflict` uses `!==` instead of "server newer".** Any version mismatch is treated as a conflict, which is safer. All planned test cases pass.
6. **Dead components removed.** Besides the planned deletions, `SubmissionStatusView`, `SubmissionStatusDesktop`, `LatestSubmissionCard`, `PRIMARY_BUTTON_CLASS` and `DESKTOP_ACTION_BUTTON` were dropped from submission-status-view.tsx. Only the deleted flow used them.
7. **`getSubmissionFileUrl` error string.** When presign fails it now returns 'ยังไม่ได้ตั้งค่าที่เก็บไฟล์' (previously 'ระบบจัดเก็บไฟล์ไม่พร้อมใช้งาน'), matching the R2-missing wording used everywhere else.
8. **`content` default.** The Drizzle column uses `.default(sql\`'{}'::jsonb\`)` instead of `.default({})`, because the `$type<WorkPageDoc>()` typing rejects `{}`. The generated SQL is the same.
9. **Teacher view errors.** The teacher branch calls `getTeacherWorkPageView(...).catch(() => null)`, so a non-editor teacher (or any query failure) falls back to the plain detail view instead of showing an error page.
