<domain>
## Task Boundary

The user (Thai): "ตอนสร้างกลุ่มอยากให้กำหนดจำนวนสมาชิกได้ / แล้วก็ตอนสร้างห้องเรียนแล้วคนกดจอยเข้ามาอยากให้มี list นักเรียนให้เห็น
แล้วกด assign เข้ากลุ่มง่าย ๆ (นักเรียนจับกลุ่มกันเองได้ด้วย)"

1. **Member limit per group.** Add `groups.max_members` (int, nullable). The effective limit is
   `group.max_members ?? classroom.max_group_size ?? unlimited`. The create-group form gets "จำนวนสมาชิกสูงสุด" (optional number,
   1–50) and a group edit control (rename + limit) is added. The group card shows `n/limit คน` and a "เต็ม" pill when full.
   `assignStudent` and `joinGroup` enforce the effective limit (teachers get a clear Thai error; no silent overflow).
   Lowering a limit below the current member count is allowed but shows a warning; nobody is removed automatically.
2. **Student roster with easy assign** on the teacher classroom page (new segmented tab **"นักเรียน"** next to กลุ่ม / Phase / ตั้งค่า,
   default when there are unassigned students):
   - Summary chips: "ทั้งหมด N คน · ยังไม่มีกลุ่ม M คน".
   - Section **"ยังไม่มีกลุ่ม"** at the top: one row per student (`MemberIdentity`: avatar, name, email from the Clerk
     directory added on main in bc420a7), a group select showing "กลุ่ม A (3/5)", disabling full groups, and an "เพิ่ม" button. Bulk:
     checkboxes plus "ย้ายที่เลือกไปกลุ่ม…".
   - Section **"มีกลุ่มแล้ว"** grouped by group: per student "ย้ายกลุ่ม" (select) and "นำออกจากกลุ่ม".
   - A search box filtering by name/email. Optimistic UI with toasts (sonner); `router.refresh()` after actions.
   - Desktop: two-column layout (unassigned list | groups overview); mobile: stacked.
   - Remove the now-redundant "Teacher view shows raw ids" leftovers; keep `AssignStudentDialog` on the group cards (it's still handy) but
     make it share the same server actions.
   - Add a `moveStudent({ classroomId, userId, toGroupId })` server action (transaction: remove from the old group in that classroom,
     insert into the new one, enforce the limit).
3. **Student self-grouping** (teacher-controlled). Add to `classrooms`: `group_mode` enum `('teacher','self_join','self_create')`,
   default `'teacher'`:
   - `teacher`: students wait ("รอครูจัดกลุ่ม", current behaviour, restyled).
   - `self_join`: a student without a group sees the classroom's groups (name, member names/avatars, `n/limit`, "เต็ม") and taps
     **"เข้าร่วมกลุ่มนี้"**. Wire the existing unused `src/components/group/student-group-picker.tsx` / `joinGroup` action, restyled in Cocoon CI.
   - `self_create`: same as self_join, plus **"สร้างกลุ่มใหม่"** (name required; the creator becomes the first member; respects the
     classroom default limit). Teachers can still rename, edit or delete those groups.
   - In self modes a student may **"ออกจากกลุ่ม"** while their group has no submissions yet (blocked afterwards with an explanation),
     so they can switch.
   - The setting lives in the classroom settings tab: "การจัดกลุ่ม" radio — ครูจัดกลุ่มให้ / นักเรียนเลือกกลุ่มเอง /
     นักเรียนสร้างและเลือกกลุ่มเอง — plus the existing default group size.
   - The student's classroom page (`/student/classroom/[id]` with no group) is where this happens; after joining, redirect to the group
     home as today.
4. **Join flow polish:** after a student joins a classroom via invite code, if `group_mode` ≠ `teacher` take them straight to the group
   picker; otherwise to the waiting card.

5. **Delete a group** (user: "อย่าลืมกดลบกลุ่มทิ้งได้ด้วย"). Add `deleteGroup({ groupId })` (teacher of the classroom / superadmin only) and a
   "ลบกลุ่ม" action in the group card menu and on the teacher group page. Confirm dialog in Cocoon style (red/orange destructive):
   - shows what will be removed: N members (they become "ยังไม่มีกลุ่ม" and stay in the classroom), M to-dos, K submissions;
   - if the group has any submissions, require typing the group name to confirm and show "งานที่ส่งแล้วจะถูกลบถาวร";
   - deleting removes group_members, the group's to-dos (cascade), work pages / submissions of those to-dos, and group_phase_progress rows;
     R2 objects of deleted submissions are deleted best-effort AFTER the DB transaction commits (`deleteObject`).
   - after deletion, redirect to the classroom roster tab with a toast "ลบกลุ่ม … แล้ว".
   Self-created groups (self_create mode) may also be deleted by their creator only while they have no submissions.

6. **Full create / view / edit / delete for every teacher-managed entity** (user: "ทุกอย่างเลย phase / to do / กลุ่ม / นักเรียนที่ join
   มันควรที่จะเข้าได้ ลบได้ สร้างได้"). Audit after 261003-wuo (✓ exists, ✗ missing → build it):
   | Entity | Create | Open/View | Edit | Delete |
   |---|---|---|---|---|
   | Classroom | ✓ | ✓ | ✓ settings | ✗ → `archiveClassroom` (hide from lists, restorable) + `deleteClassroom` (permanent; type the name to confirm; cascades groups/phases/todos/submissions; R2 cleanup best-effort) |
   | Phase | ✓ | ✓ | ✓ | archive/restore ✓ → add permanent `deletePhase` for archived phases ("ลบถาวร" in the archived list; blocked if any group has submissions on its to-dos unless confirmed by typing the name) |
   | To-do | ✓ (multi-group) | ✓ | ✓ | archive/restore ✓ → add permanent `deleteTodo` (same rules) and "ลบงานนี้ในทุกกลุ่ม" for copies sharing `assignment_id` |
   | Group | ✓ | ✓ | ✗ → `updateGroup` (rename, member limit) | ✗ → `deleteGroup` (item 5) |
   | Student in classroom | join/add ✓ | roster tab (item 2) | move between groups (item 2) | remove from classroom ✓ (`removeStudent`) — also removes them from their group; confirm dialog shows the name |
   | Template | ✓ save | ✓ picker | ✗ → rename/description edit for custom templates | ✓ |
   Every destructive action uses one shared Cocoon confirm dialog component (title, consequences list, optional type-to-confirm,
   destructive orange button) and a toast afterwards. Every row/card in teacher lists gets an overflow menu (⋯) with
   เปิด / แก้ไข / ลบ so the actions are discoverable on mobile and desktop.
7. **Authorization hardening (found by 261003-wuo executor):** `updateTodo`, `archiveTodo`, `restoreTodo` (and the new delete/update
   actions) must verify the caller is a teacher OF THAT CLASSROOM (or superadmin), not just any teacher. Add one shared helper
   `assertClassroomTeacher(classroomId)` and use it in every teacher mutation (classroom, group, phase, todo, template-apply). Unit test it.

### Data (additive migration; the DB is shared with the LIVE site)
- `groups.max_members` int null; `classrooms.group_mode` text enum default 'teacher'. Provide a `--dry-run`/`--apply` script like
  261003-wuo (simple `ALTER TABLE … ADD COLUMN IF NOT EXISTS`); the executor runs only `--dry-run`. Update the Drizzle schema.

Out of scope: auto-grouping/random assignment, group chat, Phase 4 review, notifications.

## Implementation Decisions
- Per-group limit with the classroom default as fallback (user asked for it at group creation).
- The roster tab gives the teacher one place to see joined students and assign them quickly.
- Students can form groups themselves when the teacher enables it (user: "นักเรียนจับกลุ่มกันเองได้ด้วย"). Claude chose a 3-option setting
  (teacher / self-join / self-create) — confirm with the user in the final summary.
