# Quick Task 261004-03i: Clear deadlines with overdue / late-submission status — Summary

Deadlines are now shown everywhere a to-do appears, with เลยกำหนด / ใกล้ถึงกำหนด / ส่งตรงเวลา / ส่งช้า shown next to the review status. All deadline maths runs on UTC instants and all display uses Asia/Bangkok. Students can update a pending submission until the deadline. Teachers land on a dashboard with a matrix for each classroom and a deadline timeline across classrooms, and they set deadlines with Bangkok date + time inputs. There is no schema change.

## Task 1: Data layer (commits `0c8fc5e` RED, `07fb596` GREEN, handoff `6e311fc`)
- `src/lib/deadline.ts` is pure. It provides `getEffectiveDeadline` (todo ?? phase) and `getDeadlineStatus`, which returns none / upcoming / due_soon (≤ 48 h) / overdue / on_time / late and judges lateness on the first submission. It also has the Bangkok formatters (`formatDeadline`, `formatDeadlineDate`, `formatDeadlineShort`, `formatDeadlineRelative`, `formatLateness`) and `bangkokInputToUtc` / `utcToBangkokInput` / `bangkokDayKey`.
- The rules in `src/lib/work-page.ts` are now deadline-aware:
  - `getWorkPageLock` returns `locked` / `approved` / `deadline_passed`.
  - `canEditWorkPage` takes object input.
  - `canSubmitWorkPage` returns `mode: submit | resubmit | update` and `late`.
  - `computeOrphanFileKeys` is new.
  - A full matrix test covers status × deadline × action.
- New server action `updateSubmittedWorkPage`:
  - It locks the page and the latest scoped submission with `FOR UPDATE`.
  - It rejects a submission that has been reviewed or replaced with 'ครูตรวจงานนี้แล้ว'.
  - It updates content, textContent and `updatedAt` on the same row, and never writes createdAt.
  - It replaces the submission_files snapshot and cleans up R2 keys only when nothing else references them.
- Batched dashboard data comes from `loadClassroomSnapshots` (7 parallel `inArray` queries) plus the pure builders in `deadline-dashboard.ts`: matrix rows, group cards, counts, filters, timeline and student sections.

## Task 2: Student UI (commits `1a3ce93`, `df63fe0`, `c3b3173`, `4387630`, handoff `ad84e99`)
- New `DeadlineChip`, `DeadlineBanner` and `useNow`, a live clock that cannot cause a hydration mismatch.
- To-do page:
  - A deadline banner.
  - The work page has three modes: draft submit, a pending "อัปเดตงานที่ส่ง" bar before the deadline, and read-only after the deadline or once approved. It switches between them live.
  - The confirm dialog has update copy and the late warning.
  - History shows "อัปเดตล่าสุด …".
- Node path: a deadline line under each node and a red overdue dot. The stepper shows the phase deadline date.
- `/student/deadlines` has sections เลยกำหนด / ใกล้ถึงกำหนด · 48 ชม. / กำลังจะมาถึง / ส่งแล้ว.
