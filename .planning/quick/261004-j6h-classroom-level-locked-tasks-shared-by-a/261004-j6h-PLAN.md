<objective>
Add classroom-level tasks ("งานของห้องเรียน") to classroom phases. A classroom task is defined once on the Phase tab and materialized as one ordinary `todos` row per group (including groups created later), so work pages, submissions, review and deadlines keep working per group unchanged. Title, deadline and submission mode are locked to the classroom; description, notes (which hold the sub-todo/deliverable bullets), file requirement and files sync to every group until a teacher edits them on a group copy (per-field override). Deleting keeps copies that have submissions (detached into ordinary group tasks). Every phase task list orders by deadline ascending, undated last.

Purpose: teachers stop re-creating the same task for every group by hand, and new groups no longer miss shared tasks.
Output: additive migration (applied), schema, pure tested planner, server actions + sync hooks, Phase tab UI, locked/badged group copies, deadline ordering, deployed build.

## Locked user decisions (CONTEXT.md "Confirmed decisions" + "Update" — these win over the [confirm] items)
- D-1 (option ก): title + deadline locked at classroom level and propagated to every copy. Description/notes, sub-todos (= bullet lines inside `notes`, parsed by `src/lib/todo-deliverables.ts`; there is no separate sub-todo table), attachments (files) and file requirement are pushed to all groups but editable per group; a locally edited field is recorded in `todos.overridden_fields` and later classroom edits skip it for that copy. Non-overridden fields keep syncing.
- D-2: deleting a classroom task deletes copies of groups that have NOT submitted; copies with ≥1 `submissions` row are kept and detached (`classroom_task_id = NULL`) → ordinary group task. ConfirmDialog shows removed vs kept counts.
- D-3' (supersedes D-3): within a phase, tasks (classroom + group mixed) are listed by `deadline` ascending; tasks without a deadline after all dated ones, by existing `order_index` (then created_at). No mixed drag-reorder is required. Apply on teacher AND student views.

## Claude's discretion (decided here)
- `submissionMode` is treated like title/deadline: set on the classroom task, propagated, read-only on copies (changing it per group would split one shared task semantically).
- Overridable field ids stored in `overridden_fields`: `'description' | 'notes' | 'fileRequirement' | 'attachments'`.
- Copies get `assignmentId = classroomTaskId` so the deadline dashboard matrix ("first copy wins" by assignment) groups them into one row. The "ลบงานนี้ในทุกกลุ่ม" / archive / delete menu items are hidden for linked copies and rejected server-side.
- Classroom-level files live in a new `classroom_task_files` table (short name keeps Postgres FK identifiers ≤63 chars). R2 key scope = `attachments/{classroomTaskId}/…` (reuse `buildAttachmentKey` / `isAttachmentKeyInScope`); copies get `todo_attachments` rows sharing the same `file_key` (gid shared-key model).
- No archive state for classroom tasks (delete only); no "reset override" button (not requested).
- Safety net: partial unique index `todos (classroom_task_id, group_id) WHERE classroom_task_id IS NOT NULL` prevents duplicate copies under concurrent group creation; inserts use `onConflictDoNothing()`.

```ts
export const LOCKED_FIELDS = ['title', 'deadline', 'submissionMode'] as const;
export const OVERRIDABLE_FIELDS = ['description', 'notes', 'fileRequirement', 'attachments'] as const;
export type LockedField = (typeof LOCKED_FIELDS)[number];
export type OverridableField = (typeof OVERRIDABLE_FIELDS)[number];
export interface TaskFileSpec { fileKey: string; fileName: string; contentType: string; fileSize: number; uploadedBy: string }
export interface TaskFieldValues { title: string; description: string | null; notes: string | null;
  submissionMode: 'group' | 'individual'; fileRequirement: FileRequirement; deadline: Date | null }
export interface ClassroomTaskSpec extends TaskFieldValues { id: string; phaseId: string; orderIndex: number; files: TaskFileSpec[] }
export interface CopyState extends TaskFieldValues { todoId: string; classroomTaskId: string; groupId: string;
  overriddenFields: string[]; attachmentKeys: string[]; hasSubmission: boolean }
export interface SyncPlan {
  inserts: { classroomTaskId: string; groupId: string; phaseId: string; values: TaskFieldValues; files: TaskFileSpec[] }[];
  updates: { todoId: string; set: Partial<TaskFieldValues> }[];
  attachmentInserts: { todoId: string; file: TaskFileSpec }[];
  attachmentDeletes: { todoId: string; fileKey: string }[];
  deletes: string[];   // todo ids (task gone, copy has no submission)
  detaches: string[];  // todo ids (task gone, copy has a submission)
}
export function planClassroomTaskSync(input: { groupIds: string[]; tasks: ClassroomTaskSpec[]; copies: CopyState[] }): SyncPlan;
export function computeOverrideMarks(input: { current: TaskFieldValues; updates: Partial<TaskFieldValues>; existing: string[] }):
  { lockedViolation: LockedField | null; overriddenFields: string[] };
export function summarizeDelete(copies: Pick<CopyState, 'hasSubmission'>[]): { removed: number; kept: number };

// src/lib/todo-order.ts
export function compareTodosByDeadline(a: OrderableTodo, b: OrderableTodo): number;
export function sortTodosByDeadline<T extends OrderableTodo>(list: readonly T[]): T[]; // returns a new array
type OrderableTodo = { id: string; deadline: Date | string | null; orderIndex: number; createdAt: Date | string };
```
