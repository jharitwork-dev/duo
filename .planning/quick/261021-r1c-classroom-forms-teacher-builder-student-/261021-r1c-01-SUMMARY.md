# Quick 261021-r1c Plan 01: Classroom forms data layer + teacher server API Summary

This plan adds the foundation for classroom forms: framework-free domain logic in `src/lib/forms.ts` (38 vitest tests), the Drizzle schema for 4 new tables plus nullable `form_id` on `todos` and `classroom_tasks`, and a hand-written idempotent migration that has never been run. It also makes classroom-task sync copy `form_id` to every group copy like a locked field, adds the teacher form actions (including `addFormToPhase`) and shared queries, and blocks the work-page actions for form-linked todos.

## Contracts for plans 02-04

- `src/lib/forms.ts` exports every contract listed in the plan, with the exact signatures.
- `src/server/queries/form.ts` exports `FormRow`, `loadFormRow(formId, tx?, {lock?})`, `loadFormQuestions(formId, tx?)`, `loadFormAudience(formId, tx?)`, `loadClassroomRoster(classroomId, tx?)`, `countFormResponses(formId, tx?)` and `countLinkedTasks(formId, tx?)`. It also exports `getClassroomForms(classroomId, userId)` and `getFormForEditor(formId, userId)`, which return null when the caller is not allowed. Extra exported types: `ClassroomFormListItem`, `FormEditorData`, `FormLinkedTask`.
- `src/server/actions/form.ts` exports `createForm`, `updateFormSettings`, `setFormStatus`, `deleteForm`, `addQuestion`, `updateQuestion`, `deleteQuestion`, `moveQuestion` and `addFormToPhase`. All return `ActionResult`.

## Step 5 finding (formId never clobbered)

- `updateTodo` (todo.ts) and `updateClassroomTask` (classroom-task.ts) map fields one by one into `.set()`. Their zod schemas have no `formId`, so neither function can overwrite or clear it. Every other `.set()` in those files touches only orderIndex or isArchived.
- The detach path in `syncClassroomTasks` (task deleted, copy has a submission) sets only `classroomTaskId: null`, `overriddenFields` and `updatedAt`, so the copy keeps its `formId`.
- Sync inserts spread `ins.values`, which includes `formId`, and updates spread `u.set`. Both write `formId` without needing an explicit mapping.

## Work-page guard

`formTaskWorkPageBlock(access.todo)` runs right after `resolveWorkPageAccess` in saveWorkPage, submitWorkPage, updateSubmittedWorkPage, createWorkPageUploadUrl and attachWorkPageFile. `work-page-access.ts` needed no change: `resolveWorkPageAccess` → `resolveStudentTodoAccess` uses `db.query.todos.findFirst` without a `columns` restriction, so `formId` is already included. No other student action inserts into `submissions` (submission.ts only presigns downloads).
