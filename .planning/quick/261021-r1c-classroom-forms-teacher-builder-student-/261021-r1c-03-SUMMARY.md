# Quick 261021-r1c Plan 03: Student form flow + submission bridge Summary

Students now answer classroom forms at `/forms/{formId}`. The page is full-screen in the build.Innovator CI and shows one question per screen, Typeform style. The server works out the respondent's membership, group and owner key itself. A save upserts the response by (form_id, owner_key) and, in the same transaction, creates or updates a pending `submissions` row for each viewable form-linked to-do of the student's group. Classroom editors who open the same URL get a preview that never saves.

## Contracts for Plan 04 (src/server/queries/form-response.ts, server-only)

```ts
export type FormQuestion = FormQuestionDef;
export interface RespondentFormView {
  form: { id; classroomId; title; description: string | null; responseMode: ResponseMode; status: FormStatus; closesAt: Date | null; effectiveStatus: FormStatus };
  questions: FormQuestion[];
  eligibility: FormEligibility; // { visible, canRespond, reason: EligibilityReason, ownerKey: string | null }
  respondent: { classroomId: string; groupId: string | null; ownerKey: string }; // ownerKey '' when none
  response: null | { answers: FormAnswers; submittedAt: Date; updatedAt: Date; lastEditorName: string };
}
getFormForRespondent(formId, userId): Promise<RespondentFormView | null>   // null unless visible
export type StudentFormState = 'todo' | 'done' | 'closed' | 'no_group';
export interface StudentFormItem { id: string; title: string; closesAt: Date | null; responseMode: ResponseMode; state: StudentFormState }
getStudentForms(classroomId, userId): Promise<StudentFormItem[]>          // [] when not a classroom student
getPendingFormCounts(userId, classroomIds): Promise<Record<string, number>>
```

`FormEligibility` is exported from `src/server/form-respondent.ts`. The phase-locked state for the todo card is not part of `RespondentFormView`; Plan 04 should take it from the todo's own phase/workPage access. The flow returns to `/todo/{id}` when it is opened with `?todo={id}`.
