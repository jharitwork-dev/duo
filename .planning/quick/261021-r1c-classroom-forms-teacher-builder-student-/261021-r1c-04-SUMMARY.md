# Quick 261021-r1c Plan 04: Student form entry points Summary

Students can now find classroom forms from their own pages. The group page and the no-group classroom page show a "แบบฟอร์มที่ต้องตอบ" section, and the multi-classroom home shows "แบบฟอร์มรอตอบ {n}" on each classroom that has forms waiting. Form-linked to-dos show a "ตอบแบบฟอร์ม" button where the work page used to be.

## Details

- **StudentFormCards** is a server-safe component that renders nothing when the list is empty. Each card links to `/forms/{id}`, shows a state pill (ยังไม่ตอบ in orange, ตอบแล้ว in green, ปิดแล้ว and ต้องเข้ากลุ่มก่อน muted) and "ปิดรับ {formatDateTime}" when a close date is set.
- **Group page (student branch):** `getStudentForms(...).catch(() => [])` runs in parallel with the responsible-teachers fetch. The section renders under ResponsibleTeachersLabel, before the preview notice and the node path.
- **Classroom page (no group):** the section sits at the top of PAGE_BODY, above the picker or the waiting card.
- **Student home:** `getPendingFormCounts(...).catch(() => ({}))` feeds a `PendingFormsPill` inside the classroom cards, which the page renders inline. The unused `ClassroomCards` client component also got an optional `pendingFormCounts` prop so the two stay consistent.
- **Form-linked to-do:** when `todo.formId` is set, `getFormForRespondent(...).catch(() => null)` drives FormTaskCard. StudentWorkPage, with its editor, file manager and submit/update buttons, is not rendered. Teacher details, reviewer notes, the deadline banner, history and the comment thread are unchanged. `getSubmissionHistory` already returns every todo column through `resolveStudentTodoAccess`, so `formId` needed no query change.
